## 一、录制前准备（10 分钟）

1. 启动服务并确认可用：`cd src && python3 -m uvicorn web.app:app --host 127.0.0.1 --port 8765`
2. 浏览器全屏（建议 1440×900 以上窗口），隐藏书签栏与扩展图标，关闭所有通知。
3. 提前**跑通一次完整流程并清空检索历史**，避免录到加载失败或旧结果。
4. 准备一个能稳定出结果的研究问题（见分镜 02）；网络不佳时先确认该问题在 60 秒内能返回结果。
5. 模型已配置好并测试通过（未配置会降级为文本匹配，推荐理由会变弱，不建议演示）。
6. 录屏工具：OBS / 系统自带录屏；麦克风单独录旁白更稳，后期对齐。
7. 画面内不要出现 API Key、账号密码、私人文件路径。

## 二、分镜表

| # | 时长 | 画面 | 旁白（逐字稿，可直接念） |
| --- | --- | --- | --- |
| 01 | 0:00—0:20 | 首页首屏，缓慢下滚到"研究工作流"段落 | 研究生找文献有三个断点：不懂研究问题的检索工具、只存条目的文献管理器、无法核对的对话模型。研索把这三段连成一条由智能体实际执行、每一步都能核对的任务链。 |
| 02 | 0:20—0:45 | 切到 `/app`，在搜索框逐字输入研究问题，并高亮输入框 | 我输入的不是关键词，而是一个研究问题：图神经网络预训练，如何改善分子性质预测。它同时包含方法、研究对象和一个明确的判断目标。 |
| 03 | 0:45—1:15 | 展开"查询规划"面板，指出方法词与年份条件 | 系统先把问题拆成标准学术术语和聚焦检索短语，并把方法、对象和年份约束保留到检索里。这些约束不会被"多找几篇"的冲动放宽。 |
| 04 | 1:15—1:50 | 检索进行中：并行来源、每轮进度、候选计数 | 接下来是实际执行：并行调用 arXiv、OpenAlex、Crossref、Semantic Scholar、Europe PMC 和本地索引，合并 DOI 与 arXiv 别名去重，再沿已召回文献的参考文献扩展候选。每一轮的新增、重复和拒绝数量都留在界面上。 |
| 05 | 1:50—2:20 | 结果列表，滚动展示推荐理由摘要 | 结果按研究用途组织，不是按引用量排序。引用量和期刊声望不决定推荐顺序——这一点很多同类工具做不到。 |
| 06 | 2:20—2:50 | 打开一篇文献，展开"推荐理由"与证据片段，鼠标逐句划过 | 每条理由都必须基于检索到的标题或摘要，展开就能看到原文片段。理由里的话在原文里找不到，就不能作为推荐依据。 |
| 07 | 2:50—3:20 | 加入项目 → 生成对比矩阵，点开单元格出处 | 文献进入课题后，可以生成对比矩阵：方法、数据集、指标、结论逐列提取，每个单元格都带原文出处。人工修改的单元格不会被批量重跑覆盖。 |
| 08 | 3:20—3:50 | 修改一处证据 → 关联产物出现"待复核"标记 | 证据带来源哈希和位置。改动证据后，依赖它的矩阵、综述和演示报告会回到待复核状态，避免旧结论被悄悄沿用。 |
| 09 | 3:50—4:15 | 导出 DOCX、PPTX；打开导出文件看来源备注 | 最后导出：可编辑的 Word、原生文本框 PPTX、PDF 或 Markdown，出处随文件带走。 |
| 10 | 4:15—4:30 | 回到架构图或首页标题页，字幕收尾 | 研索不承诺替代研究判断。数据源失败就降级，资料不足就说不足，模型不可用时保留原文和人工流程。现在已有 148 项自动化回归通过——剩下的，是把它交给真实课题去验证。 |

## 三、旁白配音提示
