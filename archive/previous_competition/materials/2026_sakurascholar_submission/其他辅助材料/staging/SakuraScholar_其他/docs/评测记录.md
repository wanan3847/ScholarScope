### 2.1 SPAR2 引擎结果（2026-08-15 实测，DeepSeek + 真实检索，`--engine spar2`）

评测链路自 2026-08 起切换到基于成熟 SPAR 架构的 `SPAR2Engine`（见
`docs/superpowers/specs/2026-08-12-spar2-engine-design.md`）。与旧自研流水线（2026-08-09
F1@10=0.0171）同口径对比：

| 测试集 | 样本数 | F1@10 | Recall@20 | P@10 | 平均 LLM 调用 | P50 延时 | 说明 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| RealScholarQuery | 5 | **0.0564** | 0.0400 | 0.1000 | 18 | 42.8s | 5 条小样本（2026-08-15，稳定跑完） |
| RealScholarQuery | 10 | **0.0579** | 0.0440 | 0.1000 | 17 | 51.4s | 10 条样本（2026-08-14） |

对比：旧自研流水线 real_scholar 全量 F1@10=0.0171。SPAR2 约为旧方案的 3.3 倍，
且全部查询稳定出结果（无异常中断）；每查询硬超时 170s（`SPAR2_DEADLINE` 环境变量可调）。

SPAR2 关键改进（相对 vanilla SPAR / 本地旧方案）：
1. QueryPlanner 输出 10 关键词 + 8 条语义搜索短语（原版 SPAR 输出整句，词法引擎召回极差）；
2. 检索通道：arXiv API 布尔检索（替代无 key 的 Google serper）、OpenAlex
   `title_and_abstract.search` + `title.search` + 全文 `search`（mailto→api_key 自动降级）、
   CrossRef（DOI 通道，服务 litqa2/paper_finder）、本地 PaSa 20 万标题 BGE-small 语义召回；
3. BGE 语义预排（本地零成本，把"词面零重叠"的语义型 gold 送进 LLM 判分视野）；
4. LLM 批量判分改为行式打分（JSON 解析失败率从 ~25% 降到 0~4 次/条）；
5. RefChain 引用扩展：OpenAlex referenced_works + cites + CrossRef references（1 跳）；
6. 截止日期过滤（PaSa `published_time`），避免评测日后论文污染排序。

已知短板（后续优化方向）：
- 候选召回仍是瓶颈：gold 集合平均 9~44 篇/条，SPAR2 目前命中 1~4 篇/条；
- Semantic Scholar 长期 429，无法用其语义通道和 corpusId 映射（paper_finder 出分依赖 S2 恢复）；
- 本地语义索引仅覆盖 59% 语料（.cache/pasa_titles_bge_small.f16.npy 117,248/199,447 行，
  SAKURA_LOCAL_EMBED_RESUME=1 可续跑补全），且 PaSa 语料不含 2023-24 论文。

### 2.2 SPAR2 引擎迭代搜索升级（2026-08-19 代码改动）

本次改动集中在 `src/agent/spar2/` 和 `src/run_eval.py`，目标把 F1 从 0.05 级别拉到 0.2+ 级别：

1. **迭代搜索循环**（`engine.py`）：把单次检索改为最多 2 轮 BFS 迭代。第一轮用 QueryPlanner
   原始关键词+短语全通道检索；第二轮用文档驱动查询（`generate_queries_from_docs`，1 次 LLM
   调用生成 5 条新查询）只走 arXiv+OpenAlex。停止条件：高分论文 >= 8 篇或超时 170s。
2. **文档驱动查询生成**（`query_planner.py`）：新增 `generate_queries_from_docs()` 函数，
   根据 top-5 高分论文的标题/摘要生成新搜索查询（"论文标题风格"短语），覆盖语义型 gold。
3. **引文扩展加宽**（`expand.py`）：`max_seeds` 3→5、`refs_per_seed` 15→25；
   engine.py 中 RefChain 判分上限 40→60。**新增 CrossRef cited_by 方向**（2026-08-19 晚），
   实现参考文献（references）+ 被引（cited_by）双向引文扩展，每查询多召回 30-50 篇候选。
4. **预筛放宽 + 语义保底**（`engine.py`）：`max_judge` 150→200；预筛公式
   `0.55*sem+0.30*lex` → `0.60*sem+0.25*lex`；新增语义保底机制（BGE 余弦 >= 0.65 的论文
   保证进入判分池，不受截断影响）。
5. **判分质量提升**（`judge.py`）：摘要截断 400→600 字符；prompt 改为三维度评判
   （主题匹配/方法相关性/意图覆盖）；`batch_size` 12→10；`judge_threshold` 0.45→0.40。
6. **S2 corpusId 本地缓存**（`run_eval.py`）：新增 JSON 缓存文件
   `src/data/s2_corpus_id_cache.json`，先查缓存再调 S2 API，成功映射增量持久化，
   S2 429 时从缓存读取。paper_finder 不再因重复映射失败归零。**新增一次性批量预填充脚本**
   `scripts/prefill_s2_cache.py`（2026-08-19 晚；2026-08-23 移至仓库根 `scripts/` 并修复路径），
   S2 恢复后可遍历本地已知论文列表
   （PaSa 数据库 + 评测集 gold）批量获取 corpusId 并写入缓存。
7. **本地语义索引补全**（`retrieval/local_corpus.py`）：当前覆盖 117,248 篇论文
   （`.cache/pasa_titles_bge_small.f16.npy` 85.9 MB），设置 `SAKURA_LOCAL_EMBED_RESUME=1`
   可续跑补全至 100% 覆盖（199,447 篇），提升语义型 gold 在本地通道的召回率。

改动后 `src/tests/` 单元测试全绿（当时 8 个，覆盖引擎基础逻辑与
结构化输出/反馈闭环回归；2026-08-21 前旧 15 模块测试随源码一并精简）。
待全量评测验证实际 F1 提升。

### 2.4 F1 底层优化（2026-08-21 代码改动）

对照本地 gold 数据计算的理论上限（满分假设：检索全中且排序完美）：

| 测试集 | 规模 | gold 均值/中位 | 理论 F1@5 | 理论 F1@10 | 理论 F1@20 |
| --- | --- | --- | --- | --- | --- |
| RealScholarQuery | 50 | 15.8 / 10 | 0.582 | **0.657** | 0.598 |
| AutoScholarQuery | 1000 | 2.4 / 2 | 0.553 | **0.353** | 0.203 |
| LitQA2 | 199 | 2.0 / 2 | 0.575 | **0.336** | 0.183 |
| paper_finder_bench | 267 | 0.3 / 0 | 0.064 | **0.038** | 0.023 |

当前 SPAR2 F1@10 ≈ 0.058，离 real_scholar 理论上限 0.657 还有约 11 倍空间，
瓶颈在"候选未进判分池 / 判分排序质量"，而非指标公式。本次代码改动：

1. **判分补足通道**（`engine.py`）：循环检索后，若相关论文 < 10 且未超时，
   对 `_pre` 最高的未判分候选分块补判（每块 40、最多 80，够 10 篇即停），
   修复"gold 已被召回但因超出判分预算被丢弃"的召回漏洞；
2. **三维度判分 prompt**（`judge.py`）：主题匹配 / 方法相关性 / 意图覆盖
   三维评判（此前文档写了但代码仍是单维 0-1 打分），摘要窗口 300→600 字符，
   batch 15→12；解析失败重试保留；
3. **候选上限提升**（`retrievers.py`）：arXiv 80→120、OpenAlex per_page 30→40、
   CrossRef rows 30→50、本地语义 top_k 500→800（`engine.py` 默认值），
   额外候选只进 BGE 预筛，实际判分仍受 deadline/补判上限约束。

验证：`src/tests/` 当时 12 个单元测试全绿（新增判分 prompt、补判预算、
候选上限回归测试；2026-08-21 晚扩展至 22 个，见 §2.6）。
真实 F1 提升需全量评测确认（见下方运行命令）。

### 2.5 本地模型优先 + 检索/排序结构性修复（2026-08-21）

**工作流**：先本地 ollama（qwen3:8b）迭代验证，效果可接受后再用 DeepSeek
确认；本地模型质量不足时继续优化代码而不是烧 API。当日实测对比（real_scholar
前 3 条，同一批查询）：

| 模型 | F1@10 | Recall@20 | P@10 | P50 延时 | 说明 |
| --- | --- | --- | --- | --- | --- |
| qwen3:8b（本地） | 0.0645 | 0.0476 | 0.1000 | 203s | 单条最高 F1@10=0.1935 |
| DeepSeek（API） | 0.0816 | 0.0591 | 0.1333 | 155s | 单条最高 F1@10=0.1935 / 0.2105 |

对照改动前 DeepSeek 10 条 F1@10=0.0579，3 条小样本下已明显上移；
query 0（"smaller dataset pretraining"）在补判扩容后从 0 升至 F1@10=0.21
（诊断运行），但该查询跨运行波动大（0~0.21），待全量评测取均值。

当日定位并修复的结构性问题：

1. **`--llm` 对 SPAR2 静默失效**：`run_eval.py` 构造 `SPAR2Engine()` 未传
   `llm_chat`，`--llm ollama/deepseek` 被忽略，实际走 `spar2/llm.py` 的
   DeepSeek 环境变量。已改为传入，且 `SPAR2Engine` 兼容 BaseLLM 与裸函数。
2. **ollama 404 根因**：`.env` 的 `SAKURA_LLM_MODEL=deepseek-chat` 被 ollama
   模式继承，请求不存在模型返回 404。已改独立变量 `OLLAMA_MODEL`（默认 qwen3:8b）。
3. **deadline 未下沉到判分内部**：单次 `judge_docs` 可拖到 5 分钟（P50 297s）。
   已支持 `deadline` 参数逐批截断 + `max_workers`（本地 8 / API 4），P50 降至 ~155-180s。
4. **本地模式自适应**：判分 batch 12→6、最终排序 6:4 融合 LLM+BGE 语义分、
   轮预算让给第二轮、第二轮种子按 BGE 语义分选（原按插入顺序取前 5，是 bug）。
5. **查询规划三层合并**：LLM 关键词优先 → 查询短语 bigram 提取（"data pruning"）→
   规则兜底词；此前兜底词占满 12 个名额，把 LLM 判别词挤出。
6. **arXiv 检索重构**：每个 AND 组合/短语独立请求（原所有 OR 子句共用一个
   max_results，被通用词挤掉）；停用词不再删 "data"/"training"/"model"；
   连字符原形变体（`data-efficient` vs `dataefficient`）；多词短语优先；
   第二轮用已找到论文标题提取判别词（零 LLM 成本）。
7. **OpenAlex**：短语全文检索改 `sort=relevance_score:desc`、per-page 40→80/100。
   ⚠️ 2026-08-21 当天 OpenAlex 免费额度被评测烧光（429，UTC 零点重置），
   当日后续评测实际无 OpenAlex 通道。
8. **判分补足扩容**：top-up 从固定 80 篇改为 deadline 内持续判分（API 240 /
   本地 120，每块 60，够 10 篇相关即停）；ref 候选判分补 `judged=True`。
   ——这是 query 0 从 0 到 F1@10=0.21 的关键修复：gold 早已在候选池（BGE
   sem 0.84），但排在补判预算之外从未被 LLM 判分。

### 3.2 SPAR2 引擎现状核对（2026-08-23 代码）

与 §2.2 / §2.4 记录的版本相比，引擎当前参数如下（`src/agent/spar2/engine.py`）：

1. **并行 5 通道检索**：Round 1 的 arXiv / OpenAlex / CrossRef / S2 / 本地语义
   五通道并行执行（`ThreadPoolExecutor(max_workers=5)`），单通道 40s 硬超时，
   总耗时由最慢通道决定而非累加；全通道失败时生成兜底候选，避免空结果。
2. **迭代检索最多 3 轮**（`max_rounds=3`）：Round 1 全通道原始查询；
   Round 2 文档驱动查询 + 标题词补充，走 arXiv + OpenAlex + 本地；
   Round 3+ 只走 arXiv + 本地。每轮判分预算随轮次放宽
   （第一轮 API 170 / 本地 90，后续 API 200 / 本地 120），本地模式第一轮少判、
   把预算让给第二轮。
3. **预筛权重调整**：`0.70*BGE 语义 + 0.20*词面 + 0.10*被引归一`
   （§2.2 记录为 0.60/0.25）；语义保底阈值 0.65 → **0.40**、保底数量上限 60 篇，
   提升语义型 gold 进入判分池的概率。
4. **OpenAlex 摘要补全**（`_enrich_abstracts`）：判分前对缺摘要候选按
   openalex_id / arxiv_id / DOI 批量补摘要（单次调用），提升 LLM 判分质量。
5. 其余常驻机制不变：判分补足 top-up API 400 / 本地 120（每块 80）、
   RefChain 引用扩展（API 2 跳 / 本地 1 跳，seeds≤6、refs_per_seed=25、
   判分上限 API 100 / 本地 40）、top-30 相对精排仅 API 模式、
   本地模式最终分 6:4 融合 LLM 判分 + BGE 语义分。

待全量评测验证这些调整对 F1@10 的实际影响。

运行命令：

```bash
cd src
SPAR2_DEADLINE=170 python3 run_eval.py --n 10 --benchmarks real_scholar --engine spar2 \
  --real --llm deepseek --output /绝对路径/结果.json
```

运行环境备注：
- Semantic Scholar 匿名共享池持续 429（无免费 key 时），系统已实现串行限流、429 退避、
  线程安全熔断（连续 3 次 429 熔断 5 分钟），S2 恢复后自动全量生效；
- OpenAlex 2026 起按 key 计费，匿名额度每日重置；默认不携带付费 key（余额不足会 429），
  走 mailto 免计费通道；
- arXiv API 偶发超时，已加 10s 超时 + 重试 + 熔断；
- 语义型 gold（标题/摘要不含查询词，如 "diffusion models + RL" → `Planning with Diffusion`）
  依赖 S2/OpenAlex 语义通道，S2 长期 429 时此类查询 F1 会明显偏低；
- 真实 LLM 模式效率：P50 ≈ 15s/条，API 调用 3~5 次/条（QDAR 预算控制 + 级联打分）。
- 2026-08-10 降级增强：真实模式新增标题风格查询（去除疑问词/元词，仅保留实体与方法词），
  并把检索 query 下限提高到 4 条；Semantic Scholar 长期 429 时由 OpenAlex/CrossRef 接管
  语义召回。没有申请 key 或教育邮箱也可运行；拿到 `S2_API_KEY` 后无需改代码即可热切换。
- 2026-08-11 新增 `local_corpus`：使用 PaSa 官方公开 `paper_database/id2paper.json`
  （约 20 万篇标题）建立倒排索引，并可选用 FastEmbed BGE-small 建立本地向量缓存。
  该语料不含 query→gold 映射，不读取评测答案；只作为 S2/OpenAlex 的断网降级通道。
- 2026-08-11 将真实模式切回成熟 PaSa/SPAR 主线：Crawler 多查询不再只对 hard
  查询启用；Selector 后保留 RefChain 二轮检索，并修复 RefChain 调用统计累计。
- 2026-08-11 修复 arXiv 检索：短查询按关键词 AND 而非整句精确短语，并支持
  PaSa `source_meta.published_time` 截止日期，避免评测日期后的论文污染排序。
