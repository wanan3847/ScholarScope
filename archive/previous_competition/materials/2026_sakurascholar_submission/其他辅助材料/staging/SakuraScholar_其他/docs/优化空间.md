## 3. 已完成优化（2026-08-21）

### 3.1 基础链路修复
- `--llm` 真正传入 SPAR2 引擎（此前被静默忽略，实际一直走环境变量）。
- ollama 404：`SAKURA_LLM_MODEL` 与 ollama 模型名解耦（新增 `OLLAMA_MODEL`）。
- deadline 下沉到判分内部（单次判分不再拖 5 分钟）+ 并行判分
  （本地 8 / API 4 worker）。
- Web/CLI 启动断链修复（`feedback_loop` / `graph_synthesizer` 恢复）。

### 3.2 检索层
- **新增 Semantic Scholar 语义通道**（此前 SPAR2 完全没有 S2；返回 corpusId
  直接服务 paper_finder）。
- arXiv：每个 AND 组合/短语独立请求（原 OR 大查询被通用词挤掉）、
  连字符原形变体、多词短语优先、停用词不再误删 data/training/model。
- OpenAlex：短语检索改相关度排序、per-page 40→80/100。
- 第二轮用已找到论文标题提取判别词（零 LLM 成本）。

### 3.3 查询规划
- 三层合并：LLM 关键词优先 → 查询短语 bigram 提取 → 规则兜底词
  （修复"兜底词占满名额、LLM 判别词被挤出"）。

### 3.4 判分/排序
- 三维度判分 prompt（主题/方法/意图）、摘要 600 字符。
- 判分补足从固定 80 篇改为 deadline 内持续判分（API 400 / 本地 120）——
  query 0 从 0 → F1@10=0.21 的关键修复。
- 本地模式 6:4 融合 LLM+BGE 语义分；第二轮种子按 BGE 语义分选（修复
  "按插入顺序取前 5"的 bug）。

### 3.5 数据/去重
- 同论文双条目合并（arXiv 与 `10.48550/arxiv.XXXX` DOI 互为别名）。
- 诊断工具：`SAKURA_CAND_DUMP=1`（候选池转储）、`SAKURA_JUDGE_DEBUG=1`。
