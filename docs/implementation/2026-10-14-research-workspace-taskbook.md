# 研索 AI Research Workspace 开发任务书

制定日期：2026-10-14
状态：继续实施（2026-10-14）。此前完成的是基础工程闭环，尚未证明智能分析与真实检索效果达到原始方案要求。原始调研全文保存在 [原始方案](docs/implementation/2026-10-13-research-workspace-original.md)，本任务书保留其 V1、V2、V3 的全部产品要求；各项实现和验收范围见 [验收记录](docs/implementation/research-workspace-verification.md)。

## 目标与实现原则

把研索从文献检索工具升级为以科研项目为中心的 Evidence-first Research Agent 平台。完整链路：问题 → 真实文献 → 项目知识库/PDF → 可定位证据 → 对比矩阵/问答 → 综述 → 可编辑科研 PPT → 可回访的任务与产物。综合学科能力与 Agent 编排并行建设，测井曲线预测孔渗参数作为端到端验收场景。

现有 FastAPI、React 与 SPAR2 是已有基础，保留共享 Orchestrator 入口；原文 Next.js、Docling/GROBID、STORM/PaperQA2 等是可替换技术建议，不要求整体移植参考产品或重复框架。工具应真实执行同等能力，不以聊天模拟检索、文件或流程。原方案所有功能版本均纳入下列任务，不能只完成 V1 后宣称全部完成。

延续已实现的 Atelier Zero 首页与工作台；按研究任务切换布局，不把所有功能塞进聊天框。来源失败有预算和降级，空检索不编造论文。写作、问答、图表和幻灯片共用证据对象；页码/表格/原文片段与验证状态必须可回查。没有全文只能报告摘要依据，没有依据只能报告未知。用户上传与开放获取全文优先，授权数据库接入由配置控制。引用量和期刊声望不决定推荐顺序。

## 架构与交付物

1. Web：Dashboard、Literature Explorer、PDF Reader、Evidence Matrix、Review Writer、Presentation Studio、Agent Workspace。
2. Agent Runtime：Planner、Skill Registry、Tool Executor、持久任务状态、Verifier、Artifact Manager。工具白名单，技能有版本、许可证、依赖与输入输出约束。
3. Literature Engine：多源检索、标识符规范化、元数据合并、语义检索、引文扩展。
4. Research Evidence：项目、成员、文献、文档页与位置、证据、批注、筛选决策、文稿版本、幻灯片、任务、产物及变更审计。PostgreSQL/pgvector 与 S3 可配置，本地模式提供相同功能的数据存储。
5. Export：Markdown、Word、PDF、CSV、Excel、BibTeX/RIS/JSON、可编辑 PPTX 与在线幻灯片；产物附真实来源与依赖清单。

## 全链路验收场景

输入“近三年基于测井曲线预测孔隙度、渗透率的深度学习方法”，按绝对当前日期推算年份，通过真实 Orchestrator 搜索目标 30 篇（真实匹配不足时保留实际数量并明确说明）；选入项目，关联 PDF 或摘要来源，提取方法/数据集/指标/创新点，展示并核对矩阵原文定位；生成真实引文的综述及 12 页可编辑组会 PPT；修改证据后检查关联产物的待复核状态；重启恢复项目和任务；由第二账号验证协作权限。

检索返回数量和外部 API 可用性不是允许造假的理由。受控接口契约测试与实际联网检索分别记录；测试文献不作为产品默认资料。无模型时使用原文抽取与明确标记的证据整理降级，不能输出伪造模型答案。
